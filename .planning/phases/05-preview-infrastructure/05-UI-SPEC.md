# Phase 5 — UI Design Contract

> Visual and interaction contract for Markdown Preview rendering. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Native iOS (SwiftUI) |
| Framework | WKWebView + HTML/CSS rendering |
| Component library | Apple UIKit (WebKit) |
| Icon library | SF Symbols (system native) |
| Font | -apple-system, BlinkMacSystemFont (system font stack) |

**Note:** This phase does NOT use shadcn (web framework). iOS app uses native SwiftUI for UI chrome, WKWebView for markdown content rendering. CSS is injected into WKWebView context.

---

## Spacing Scale

Applied to **rendered HTML/CSS content** within WKWebView:

| Token | Value | Usage |
|-------|-------|-------|
| sm | 8px | Inline code padding, list item spacing, table cell padding |
| md | 12px | Paragraph margins, code block padding |
| lg | 16px | Section vertical spacing (headings, blocks) |
| xl | 24px | Document-level top/bottom margins |

Applied to **native iOS UI chrome** (nav bar, buttons, toolbar):
- Standard iOS safe area margins: 16px horizontal on iPhone
- Standard iOS component heights: 44px minimum touch target (links in preview are interactive)

**Exceptions:**
- Code blocks: right-padding includes scrollable overflow (~400px max content width before horizontal scroll)
- Tables: cell padding varies by content; min 8px, max 12px per cell
- Deep nesting in lists: each level adds 16px left margin

## Typography

Rendered content uses **system font stack** with CSS cascading. Defined sizes and weights for semantic elements:

| Role | Size | Weight | Line Height | CSS Applied To |
|------|------|--------|-------------|----------------|
| Body | 16px | 400 (regular) | 1.6 | `body`, paragraphs |
| Label | 14px | 400 (regular) | 1.5 | table cells, list items |
| Heading 1 | 2em (32px) | 600 (semibold) | 1.2 | `h1` |
| Heading 2 | 1.5em (24px) | 600 (semibold) | 1.2 | `h2` |
| Heading 3 | 1.25em (20px) | 600 (semibold) | 1.2 | `h3` |
| Code | 0.9em (14px @ 16px body) | 400 (regular) | 1.4 | `code`, `pre`, monospace |
| Strong | 16px | 700 (bold) | 1.6 | `strong`, `**text**` |
| Emphasis | 16px | 400 (italic) | 1.6 | `em`, `*text*` |

**Font family cascade (applied globally to HTML):**
```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "Roboto", "Helvetica Neue", sans-serif;
```

**Monospace (code blocks, inline code):**
```css
font-family: 'Menlo', 'Monaco', 'Courier New', monospace;
```

## Color

### Native iOS UI (SwiftUI components)

| Role | Light Mode | Dark Mode | Usage |
|------|-----------|-----------|-------|
| Text Primary | #000000 | #FFFFFF | Navigation bar text, labels |
| Text Secondary | #666666 | #CCCCCC | Disabled text, hints |
| Background Dominant | #FFFFFF | #1A1A1A | Screen background |
| Background Secondary | #F5F5F5 | #2A2A2A | Toolbar, card backgrounds |
| Separator | #E0E0E0 | #404040 | Dividers between sections |

### Rendered HTML/CSS Content (WKWebView)

**CSS Variable definitions (injected stylesheet):**

```css
:root {
    /* Light mode (default) */
    --text-primary: #000000;
    --text-secondary: #666666;
    --background: #FFFFFF;
    --code-bg: #F5F5F5;
    --border: #DDDDDD;
    --link-color: #0066CC;
    --link-visited: #551A8B;
}

@media (prefers-color-scheme: dark) {
    :root {
        --text-primary: #FFFFFF;
        --text-secondary: #CCCCCC;
        --background: #1A1A1A;
        --code-bg: #2A2A2A;
        --border: #444444;
        --link-color: #4D94FF;
        --link-visited: #BB86FC;
    }
}
```

**Semantic mappings in CSS:**
- `body`: `color: var(--text-primary); background-color: var(--background);`
- `p`, `li`: `color: var(--text-primary);`
- `code`, `pre`: `background-color: var(--code-bg); border: 1px solid var(--border);`
- `table`: `border: 1px solid var(--border);` (cell borders)
- `th`: `background-color: var(--code-bg);`
- `a`: `color: var(--link-color);` (unvisited); `color: var(--link-visited);` (visited)

**Syntax highlighting colors (highlight.js integration):**

Applied via highlight.js classes. Example mappings for light/dark:

| Element | Light | Dark |
|---------|-------|------|
| `.hljs-keyword` | #A71D5D | #FF7B72 |
| `.hljs-string` | #183691 | #79C0FF |
| `.hljs-number` | #0086B3 | #79C0FF |
| `.hljs-literal` | #0086B3 | #79C0FF |
| `.hljs-attr` | #6F42C1 | #D2A8FF |

Dark mode syntax colors are applied via `@media (prefers-color-scheme: dark)` block in injected CSS.

**Color contract guarantee:**
- Rendered markdown is readable in both light and dark mode without manual user action
- No hard-coded colors in JavaScript rendering logic
- All color decisions are CSS-driven (prefers-color-scheme)

## Layout & Interaction

### WKWebView Rendering Container

**Viewport settings:**
```html
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

**Document structure in HTML:**
```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <!-- Injected CSS stylesheet -->
    <style>/* ... CSS variables, prefers-color-scheme, typography ... */</style>
</head>
<body>
    <div id="content">
        <!-- Rendered markdown HTML inserted here -->
    </div>
    <!-- Injected JavaScript libraries and initialization -->
</body>
</html>
```

**Body padding/margins (CSS):**
- Default: `margin: 0; padding: 16px 12px;` (safe area on iPhone)
- Max-width: None (responsive to viewport)
- Safe area applied in SwiftUI container (UIViewRepresentable)

### Interactive Elements in Preview

**Links:**
- Display: Blue underlined text (inline within markdown)
- Interaction: Tap → captured by WKNavigationDelegate → opens SFSafariViewController
- No visual feedback needed (phase 5 does NOT implement SFSafariViewController; phase 6 does)

**Code blocks:**
- Horizontal scroll enabled (overflow-x: auto)
- Syntax highlighting via highlight.js (colors per light/dark mode)
- User can scroll horizontally if code is wider than viewport

**Tables:**
- Horizontal scroll enabled if wider than viewport
- Cell borders visible (1px solid via CSS variable)
- Header row (th) has background color (code-bg)

### Scrolling Behavior

- Vertical scroll: Always enabled (rendered content may exceed viewport)
- Horizontal scroll: Enabled for `pre`, `code`, `table` only
- Scroll position: Not preserved when switching between edit/preview (deferred to Phase 6)

## Rendering Specification

### Markdown → HTML Pipeline

**Execution order:**
1. Read markdown string from UITextView (current state in memory)
2. Pass to markdown-it parser (JavaScript in WKWebView)
3. markdown-it renders HTML with:
   - Headings: `<h1>`, `<h2>`, `<h3>` (no higher levels required)
   - Bold/italic: `<strong>`, `<em>` (not raw `**` or `*`)
   - Lists: `<ul>`, `<ol>`, `<li>` with indentation via CSS
   - Code blocks: `<pre><code class="language-{lang}">` with highlight.js coloring
   - Inline code: `<code>` tags
   - Tables: `<table>`, `<thead>`, `<tbody>`, `<tr>`, `<th>`, `<td>` (via markdown-it-table plugin)
   - Paragraphs: `<p>` tags
4. Inject HTML into WKWebView via `loadHTMLString`
5. CSS applies prefers-color-scheme for dark mode
6. highlight.js applies syntax coloring to code blocks

**No hand-written HTML.** All markdown → HTML conversion is library-driven (markdown-it).

### Supported Markdown Elements (Phase 5 coverage)

| Element | Markdown Syntax | Expected HTML | Notes |
|---------|-----------------|----------------|-------|
| Heading 1 | `# Title` | `<h1>Title</h1>` | Rendered at 2em with semibold weight |
| Heading 2 | `## Subtitle` | `<h2>Subtitle</h2>` | Rendered at 1.5em with semibold weight |
| Heading 3 | `### Section` | `<h3>Section</h3>` | Rendered at 1.25em with semibold weight |
| Bold | `**text**` | `<strong>text</strong>` | Displayed at weight 700 |
| Italic | `*text*` | `<em>text</em>` | Displayed at font-style italic |
| Bullet list | `- item` | `<ul><li>item</li></ul>` | Indented, standard bullet glyph |
| Numbered list | `1. item` | `<ol><li>item</li></ol>` | Indented, auto-numbered |
| Inline code | `` `code` `` | `<code>code</code>` | Monospace, background per CSS variable |
| Code block | `` ```lang\ncode\n``` `` | `<pre><code class="language-lang hljs">...</code></pre>` | Syntax highlighted by highlight.js |
| Table | `\| A \| B \|\n\|---|---\|\n\| 1 \| 2 \|` | `<table>...<thead><tr><th>A</th><th>B</th></tr>...</thead>...</table>` | Borders, cell padding per CSS |
| Paragraph | `Text\n\nMore text` | `<p>Text</p><p>More text</p>` | Block-level spacing via margin |
| Link | `[text](url)` | `<a href="url">text</a>` | Color per CSS variable; tap handled by WKNavigationDelegate |

**Out of scope (not rendered in Phase 5):**
- Images (`![alt](url)`) — PREV-10, deferred
- Blockquotes, horizontal rules, strikethrough — not required by PREV-02 through PREV-09
- Nested lists beyond 3 levels — not tested, assumed to work via markdown-it defaults

### Dark Mode Application

**Mechanism:** CSS media query `prefers-color-scheme` (automatic, no Swift code needed)

```css
@media (prefers-color-scheme: dark) {
    :root { --text-primary: #FFFFFF; /* ... */ }
    /* All color uses cascade from CSS variables */
}
```

**System integration:**
- WKWebView respects system appearance setting automatically (iOS 13+)
- User changes system appearance (Settings > Display & Brightness) → WKWebView re-renders with dark mode CSS
- No `UIView.overrideUserInterfaceStyle` needed for web content (that only affects UIKit)

## Component Inventory (Phase 5)

### WKWebView Wrapper

**Component:** `PreviewView.swift` (SwiftUI UIViewRepresentable)

**Responsibilities:**
- Initialize WKWebView with bundled markdown-it, highlight.js, CSS
- Load markdown string from editor state
- Display rendered HTML
- Implement WKNavigationDelegate for link interception (phase 6)

**Inputs:** `markdownString: String`
**Outputs:** Rendered HTML in WKWebView container

**Not in scope yet (Phase 6):** Toggle UI, link handling via SFSafariViewController

### Markdown Renderer Service

**Component:** `MarkdownRenderer.swift` (SwiftUI-agnostic Swift class)

**Responsibilities:**
- Orchestrate markdown-it parsing
- Inject CSS with prefers-color-scheme support
- Generate HTML string from markdown input

**Inputs:** `markdownString: String`
**Outputs:** HTML string (ready for WKWebView.loadHTMLString)

**Dependencies:**
- Bundle resource loading (markdown-it.min.js, highlight.min.js, markdown-preview.css)

### Bundled Assets

| Asset | File | Purpose | Notes |
|-------|------|---------|-------|
| markdown-it parser | `Resources/markdown-it.min.js` | Markdown → HTML parsing | v14.1.1, bundled in app |
| highlight.js | `Resources/highlight.min.js` | Syntax highlighting for code | v11.9.0+, bundled in app |
| Stylesheet | `Resources/markdown-preview.css` | Typography, colors, prefers-color-scheme | Injected via WKUserScript |

**Verification (phase 5 testing):**
- Bundle.main.url(forResource:withExtension:) returns valid URLs for all three assets
- Assets included in Xcode Build Phases > Copy Bundle Resources
- JavaScript is minified (production-ready)

## Interaction States

### WKWebView States

| State | Trigger | Rendering | User Perceives |
|-------|---------|-----------|-----------------|
| Loading | `loadHTMLString` called | HTML parsing, CSS injection, markdown-it execution | Blank page briefly, then content appears |
| Rendered | `didFinish` navigation delegate fires | Content fully rendered, dark mode CSS applied | Formatted markdown visible, matches system appearance |
| Error (silent) | markdown-it parse fails | HTML renders empty div or placeholder | Blank page (markdown parsing should not fail in normal use; tested in phase 5) |

### CSS Media Query Evaluation

| System Setting | CSS Applied | Preview Shows |
|---|---|---|
| Light mode (default) | `@media (prefers-color-scheme: light)` variables | Light background, dark text |
| Dark mode | `@media (prefers-color-scheme: dark)` variables | Dark background, light text |
| Auto (follows system) | Responds to system setting automatically | Switches when user changes system appearance |

## Accessibility Notes (Phase 5 scope)

**Not requiring special markup in Phase 5, but informational:**
- Heading hierarchy (`<h1>`, `<h2>`, `<h3>`) is semantic and accessible to screen readers
- Links have `<a href="">` semantic HTML (phase 6 will handle tap interception)
- Code blocks are marked with language class (`language-swift`, etc.) for screen readers
- Table headers use `<th>` (semantic table structure)
- Color contrast: CSS variables must maintain WCAG AA contrast in both light and dark modes (verify in implementation)
