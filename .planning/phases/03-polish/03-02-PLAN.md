**MarkdownDocument.swift changes:**

Add a `usedEncodingFallback` property and update `load(fromContents:)` to set it:

```swift
class MarkdownDocument: UIDocument, @unchecked Sendable {
    var text: String = ""
    /// True when load(fromContents:) had to fall back to latin1 (file was not valid UTF-8).
    /// Cleared to false on each load — only meaningful immediately after a successful open.
    var(usedEncodingFallback: Bool = false

    override func load(fromContents contents: Any, ofType typeName: String?) throws {
        guard let data = contents as? Data else {
            throw CocoaError(.fileReadCorruptFile)
        }
        if let utf8 = String(data: data, encoding: .utf8) {
            self.text = utf8
            self.usedEncodingFallback = false
        } else if let latin1 = String(data: data, encoding: .isoLatin1) {
            self.text = latin1
            self.usedEncodingFallback = true
        } else {
            self.text = ""
            self.usedEncodingFallback = false
        }
    }
}
```

Fix the typo: `var(usedEncodingFallback` should be `var usedEncodingFallback` — write it correctly.

**Step 3: Add two informational alerts to EditorView.**

Add these two `.alert` modifiers to the `NavigationStack` (after the existing "Unsaved Changes" and "Save Failed" alerts):

```swift
.alert("Large File", isPresented: $appState.largeFileWarning) {
    Button("OK", role: .cancel) { }
} message: {
    Text("This file is large. Syntax highlighting has been disabled to keep the editor responsive.")
}
.alert("Encoding Changed", isPresented: $appState.encodingFallbackWarning) {
    Button("OK", role: .cancel) { }
} message: {
    Text("This file wasn't encoded as UTF-8. It has been read using a compatible encoding. When you save, it will be saved as UTF-8.")
}
```

Note: `$appState.largeFileWarning` and `$appState.encodingFallbackWarning` are Bindings to @Published Bool properties — this is the standard SwiftUI pattern for alert presentation. The alert dismisses by setting the bound value to false, which happens automatically when the user taps OK (role: .cancel means the binding is set to false).

The large file alert uses `$appState.largeFileWarning` directly as the `isPresented` binding, which means tapping OK clears `appState.largeFileWarning` — and since `isHighlightingEnabled` reads `!appState.largeFileWarning`, highlighting would re-enable after dismissal. This is the correct UX: the alert is a one-time warning, and after the user acknowledges it, highlighting stays off because `largeFileWarning` is already false once dismissed. To keep highlighting off persistently for the session, add a separate local `@State var highlightingDisabled = false` that is set when `largeFileWarning` becomes true and never reset until the file closes.

Revised approach for highlighting:
```swift
// In EditorView:
@State private var highlightingDisabled = false

// In .onChange(of: appState.largeFileWarning):
// But iOS 16 only supports single-arg onChange. Use a computed property instead:
// In MarkdownTextEditor call site:
MarkdownTextEditor(
    text: Binding(...),
    isHighlightingEnabled: !highlightingDisabled
)

// Track largeFileWarning changes with a separate onChange:
.onChange(of: appState.largeFileWarning) { isLarge in
    if isLarge { highlightingDisabled = true }
}
```

And the large file alert binding becomes a local `@State var showLargeFileAlert = false` paired with another `.onChange`:
```swift
@State private var showLargeFileAlert = false
@State private var showEncodingAlert = false

.onChange(of: appState.largeFileWarning) { isLarge in
    if isLarge {
        highlightingDisabled = true
        showLargeFileAlert = true
    }
}
.onChange(of: appState.encodingFallbackWarning) { isFallback in
    if isFallback { showEncodingAlert = true }
}
.alert("Large File", isPresented: $showLargeFileAlert) {
    Button("OK", role: .cancel) { }
} message: {
    Text("This file is large. Syntax highlighting has been disabled to keep the editor responsive.")
}
.alert("Encoding Changed", isPresented: $showEncodingAlert) {
    Button("OK", role: .cancel) { }
} message: {
    Text("This file wasn't encoded as UTF-8. It has been read using a compatible encoding. When you save, it will be saved as UTF-8.")
}
```

This way dismissing the alert does not re-enable highlighting. `highlightingDisabled` is reset when `closeCurrentDocument` is called (editor is dismissed), which is the correct scope.
