## Toolbar Placement & Structure

### Toolbar Location
- **Placement:** Above the keyboard using SwiftUI's `.toolbar(placement: .keyboard)` modifier
- **Presentation:** Automatic — appears when editor is focused, dismisses when keyboard closes
- **Lifetime:** Visible only during text editing; hidden on home screen or inactive editor

### Toolbar Container
- **Height:** 44pt (standard iOS keyboard accessory toolbar height)
- **Background:** System background that matches keyboard (`.systemBackground` in light mode, dark background in dark mode)
- **Horizontal Layout:** Left-to-right button row within safe area
- **Overflow Behavior:** If buttons don't fit in one line on small devices, use horizontal scroll OR condense to essential buttons (see Button Priority below)

### Keyboard Dismissal Button
- **Placement:** Rightmost button in toolbar
- **Label:** Keyboard dismiss icon (SF Symbol: `keyboard.chevron.compact.down`)
- **Tap Action:** Closes keyboard and returns focus to editor text
- **Always Visible:** Yes — never remove this button for space

## Button Specification

### Button Dimensions
- **Width:** 44pt (square buttons for consistency with iOS keyboard accessories)
- **Height:** 44pt (matches toolbar height, no padding)
- **Padding:** 8pt horizontal spacing between buttons (tight but touchable)
- **Min Touch Target:** 44pt × 44pt (satisfies iOS accessibility guidelines)

### Button Styling
- **Background:** Transparent (inherits toolbar background)
- **Tint Color:** System blue (`.systemBlue`) — indicates interactive buttons
- **Press State:** Opacity 0.7 when tapped (visual feedback)
- **Icon Style:** SF Symbols (monochrome, regular weight)
- **Font:** None (icons only; no text labels to conserve space)

### Button Order (Left to Right)

1. **Bold** — SF Symbol: `bold`
   - Tap action: Wrap selected text in `**markers**` or insert `**text**` if nothing selected
   - State: Always enabled

2. **Italic** — SF Symbol: `italic`
   - Tap action: Wrap selected text in `*markers*` or insert `*text**` if nothing selected
   - State: Always enabled

3. **Bullet List** — SF Symbol: `list.bullet`
   - Tap action: Prefix current line (or all selected lines in v1.1) with `- `
   - State: Always enabled

4. **Table** — SF Symbol: `tablecells`
   - Tap action: Insert 3-column × 2-row markdown table template at cursor
   - State: Always enabled

5. **Undo** — SF Symbol: `arrow.uturn.backward`
   - Tap action: Call `textView.undoManager?.undo()`
   - State: Disabled (opacity 0.4) when undo stack is empty
   - Binding: Observe `canUndo` property

6. **Redo** — SF Symbol: `arrow.uturn.forward`
   - Tap action: Call `textView.undoManager?.redo()`
   - State: Disabled (opacity 0.4) when redo stack is empty
   - Binding: Observe `canRedo` property

7. **Keyboard Dismiss** — SF Symbol: `keyboard.chevron.compact.down`
   - Tap action: Dismiss keyboard (resign first responder)
   - State: Always enabled

## Text Insertion Behavior

### Formatting Operations

#### Bold Operation (FMT-01)
```
Selection exists:
  Selected text: "hello"
  After bold tap: "**hello**"
  Cursor position: After closing markers

No selection (cursor at position):
  Cursor at position 10
  After bold tap: "**text**"
  Cursor position: After closing markers (inside, with placeholder text)

Selection spanning newlines:
  Multi-line selection in v1.1: Wrap entire selection
  Cursor position: After closing marker
```

**Undo behavior:** One undo = one bold operation (atomic grouping for marker insertion)

#### Italic Operation (FMT-02)
- Same behavior as bold, but using `*markers*` instead of `**markers**`
- Undo behavior: One undo = one italic operation (atomic grouping)

#### Bullet Operation (FMT-03)
```
Single line (cursor anywhere on line):
  Line text: "This is a bullet point"
  After bullet tap: "- This is a bullet point"
  Cursor position: At same relative position within line

Multi-line selection (v1.1):
  Three selected lines → All three prefixed with "- "
  Cursor position: Restored to original relative position

Already bulleted line:
  Line text: "- Already bullet"
  After bullet tap: "- - Already bullet" (double bullet)
  Undo behavior: One undo = entire operation
```

**Line boundary:** Use `NSString.lineRange(for:)` — never `String.split(separator: "\n")`

#### Table Operation (FMT-04)
```
Cursor at position 10:
  Insert:
    | Header 1 | Header 2 | Header 3 |
    |----------|----------|----------|
    | Cell 1   | Cell 2   | Cell 3   |

Cursor position after insertion: Start of first cell (editable)
Multi-line selection: Replace selection with table (lose selected text)
Undo behavior: One undo = entire table insertion
```

**Table template:** Exactly 3 columns × 2 rows (header + one data row)

## Undo/Redo Management

### Registration
- **When:** Before ANY text modification (not after)
- **How:** `undoManager?.registerUndo(withTarget:handler:)`
- **Atomicity:** For multi-step operations (bold = 2 insertions), use:
  ```
  undoManager?.beginUndoGrouping()
  // insert opening marker
  // insert closing marker
  undoManager?.endUndoGrouping()
  ```

### Button State
- **Undo disabled state:** When `canUndo == false`, show at 40% opacity
- **Redo disabled state:** When `canRedo == false`, show at 40% opacity
- **Binding:** Observe `textView.undoManager?.canUndo` and `.canRedo` via @State

### User Expectations
- One toolbar button tap = One undo entry
- Undo after bold = Text returns to pre-bold state (markers removed)
- Redo after undo = Markers re-inserted at same position

## Selection & Cursor Positioning

### Selection Preservation
- **Save before:** `let savedRange = textView.selectedRange`
- **Restore after:** `textView.selectedRange = calculatedNewRange`
- **Calculation:** Account for text inserted before selection (offset recalculation)

### Cursor Positioning After Formatting
- **Bold/Italic:** Cursor after closing marker (e.g., after `**` in `**text**`)
- **Bullet:** Cursor at same relative line position as before
- **Table:** Cursor at start of first data cell (ready to type)

### Edge Cases (Critical)
- **Empty selection:** Insert placeholder text (e.g., `**text**`) with text selectable
- **Cursor at line start:** Bullet correctly prefixes; doesn't create blank line
- **Cursor at EOF:** Text inserted correctly without line breaks
- **Emoji in selection:** Use NSString (UTF-16) for position math, not Swift String.count

## Interaction Contract

### Keyboard Behavior
- **Keyboard visibility:** Stays open after toolbar button tap (user can continue typing)
- **Keyboard dismissal button:** Closes keyboard without closing editor
- **Focus:** Editor remains first responder after toolbar action

### Disabled State Feedback
- **Undo/Redo buttons:** Grayed out (40% opacity) when not available
- **Other buttons:** Never disabled (always available)
- **Tap on disabled button:** No action; no visual feedback (standard iOS)

### Error Handling
- **Large file performance:** Toolbar actions complete within 100ms (no freeze)
- **Memory constraints:** No crashes on emoji-heavy text or multi-megabyte files
- **Undo stack limits:** Respect system undo manager limits (no explicit cap)

## Implementation Notes

### Placement in Code
- **Toolbar modifier:** Add to `EditorView` SwiftUI view
- **Button actions:** Wire to Coordinator methods in `MarkdownTextEditor.Coordinator`
- **State bindings:** Use @State for `canUndo` / `canRedo` observation

### No Breaking Changes
- Existing UITextView integration unchanged
- Syntax highlighting debounce (300ms) unaffected
- File auto-save unaffected
- UndoManager integration point: register before each text modification

### Testing Contract
- Test with ASCII text (baseline)
- Test with emoji: family emoji (👨‍👩‍👧), flag combinations (🏳️‍🌈), skin-tone variants (👩🏾)
- Test with CJK text (multi-byte characters)
- Test with newlines: LF (`\n`) and CRLF (`\r\n`)
- Test cursor position accuracy after each formatting operation
- Test undo/redo for all 6 operations (bold, italic, bullet, table, undo, redo)
- Test rapid button clicks (10+ taps in 1 second) — no crashes or text corruption
- Test on large files (>100KB) — toolbar operations remain responsive
